# GSK139 — Immutable releases not enabled

| | |
|---|---|
| Severity | Medium |
| Scope | Repository |
| Category | security |
| Fixable | Yes (`recommended apply`) |
| ghqr equivalent | None |

## Why it matters

By default, the assets and the tag of a published release can be replaced
afterwards. An attacker with write access, or a compromised token, can swap
a release binary or move its tag to a different commit, and consumers who
downloaded "the same version" receive different content. With immutable
releases, the assets and the tag of a published release can no longer be
modified or deleted, and the release gets an attestation consumers can
verify.

This rule is evaluated only for repositories that have at least one tag;
repositories without tags are skipped.

## How to check

```sh
gh secure-kit recommended check -R OWNER/REPO --rule GSK139
```

## How to fix

```sh
gh secure-kit recommended apply -R OWNER/REPO --rule GSK139
```

Once enabled, a published release is frozen, so a workflow that uploads
assets **after** publishing the release will fail. Change such workflows to
create the release as a draft, upload every asset, and publish the draft as
the last step.
