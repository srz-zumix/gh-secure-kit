# GSK521 - Suspended users remain organization owners

| | |
| --- | --- |
| Severity | High |
| Scope | Organization |
| Category | access_control |
| Fixable | No |
| ghqr equivalent | None |

## Why it matters

A suspended owner retains an organization role that becomes effective again
if the account is unsuspended. Review obsolete privileged memberships rather
than relying on suspension as permanent access removal. Suspension itself
blocks access; this check detects retained privileges, not active access.

The shared user classifier detects a non-null `suspended_at` on GitHub
Enterprise Server or an obfuscated Enterprise Managed User (EMU) login matching
`<hexadecimal hash>_<shortcode>` (at least 30 hash characters) on Enterprise
Cloud, including GitHub.com and hosted tenants. EMU detection is a naming-pattern
heuristic, not an authoritative suspension API. Ordinary cloud accounts do not
expose their suspension status; a pass means no matching suspension indicators.

Only Enterprise Server requires individual profile lookups for owners without
existing suspension indicators. Unreadable profiles or member lists cause a
skip unless a suspended owner is already confirmed.

## How to check

```sh
gh secure-kit recommended check --owner my-org --rule GSK521
```

## How to fix

Review the suspended owners with the identity administrator and remove or
downgrade memberships that are no longer required. Removal is not automated.
