# GSK140 — Tags are not protected by a tag ruleset

| | |
|---|---|
| Severity | Medium |
| Scope | Repository |
| Category | security |
| Fixable | Yes (`recommended apply`) |
| ghqr equivalent | None |

## Why it matters

Git tags can be deleted or force-moved by anyone who can push them. A
moved version tag silently changes what consumers get when they check out
or depend on that version. A tag ruleset that forbids tag deletion and
updates keeps published tags stable.

The rule passes when an active tag ruleset that targets all tags
(`~ALL` or `refs/tags/**`) restricts both deletion and updates. This rule is
evaluated only for repositories that have at least one tag; repositories
without tags are skipped.

## How to check

```sh
gh secure-kit recommended check -R OWNER/REPO --rule GSK140
```

## How to fix

```sh
gh secure-kit recommended apply -R OWNER/REPO --rule GSK140
```

The fix creates (or updates) a ruleset named `gh-secure-kit/tag-protection`
that targets all tags and restricts tag deletion, updates, and force
pushes. Moving tags such as `v1` or `v1.2`, which are re-pointed on every
release, would be blocked by that ruleset. They are detected as tags that
point at the same commit as a full SemVer tag with the same prefix (for
example `v1` and `v1.2.3`), and matching patterns (such as `v[0-9]` and
`v[0-9][0-9]`) are added to the ruleset's exclusions. If a moving tag does
not exist yet when the fix is applied, add its pattern to the exclusions
manually.
