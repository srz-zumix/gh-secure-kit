# GSK501 — Two-factor authentication not required for members

| | |
|---|---|
| Severity | Critical |
| Scope | Organization |
| Category | security |
| Fixable | No |
| ghqr equivalent | org-sec-001 |

## Why it matters

Without organization-wide 2FA enforcement, any member's compromised
password is enough to access every repository they can reach, including
private code and secrets.

## How to check

```sh
gh secure-kit recommended check -o ORG --rule GSK501
```

This rule reports `skip` for organizations using Enterprise Managed Users
(EMU). Managed users authenticate through the identity provider (IdP),
so GitHub's organization-level 2FA requirement does not apply. Verify MFA
enforcement in the IdP separately; `skip` does not mean MFA is enabled.

On GitHub.com, EMU is identified by an organization owner's login containing
an underscore, reserved for managed user accounts and the setup user.
Organizations on `*.ghe.com` use EMU and are also skipped, even though
their username shortcodes are hidden. Detection reuses the existing owner
list without additional API requests. If that list is unavailable on
GitHub.com, the normal 2FA check is retained. GitHub Enterprise Server
is excluded from this detection.

## How to fix

Enable "Require two-factor authentication for everyone in the
`ORG` organization" under **Organization Settings → Authentication
security**. This cannot be set through the GitHub API, so it is not
auto-fixed by `recommended apply`; members without 2FA enabled will be
removed from the organization when this is turned on, so review the
member list first.
