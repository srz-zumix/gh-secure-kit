# GSK146 - Actions lockfile not required for all workflows

| | |
|---|---|
| Severity | High |
| Scope | Repository |
| Category | actions |
| Fixable | No |
| ghqr equivalent | None |

## Why it matters

A workflow dependency lockfile records the commit resolved for each action
dependency, including transitive dependencies. The **Require lockfile** policy
blocks targeted workflows that have not been onboarded to a lockfile.

This rule checks the policy setting, not the contents or validity of a
lockfile. It passes only if one active repository or inherited policy requires
a lockfile for every workflow in the repository. Multiple partial policies are
not combined. When Actions is disabled, or policy availability or coverage
cannot be determined, the rule is skipped. Authentication and permission
errors are reported instead of being treated as skipped checks.

## How to check

```sh
gh secure-kit recommended check --repo OWNER/REPO --rule GSK146
```

## How to fix

Onboard the repository's workflows to a lockfile, verify it, and configure an
active **Require lockfile** policy targeting all workflows, either on the
repository or at a higher level. Enabling the policy before onboarding blocks
targeted workflows that are not covered. This rule does not automatically
change the policy or create a lockfile.
