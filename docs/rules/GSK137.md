# GSK137 — Environment deployment branch policy allows all branches

| | |
|---|---|
| Severity | Medium |
| Scope | Repository |
| Category | environments |
| Fixable | No |
| ghqr equivalent | None |

## Why it matters

Without a deployment branch policy, a workflow run triggered from any
branch (including a feature branch or a branch created by a pull request
from a fork) can deploy to the environment. Restricting deployments to
protected branches or an explicit allow-list of branch name patterns
ensures only reviewed, trusted code reaches environments that hold
sensitive credentials or deploy to production.

## How to check

```sh
gh secure-kit recommended check -R OWNER/REPO --rule GSK137
```

## How to fix

Configure a deployment branch policy for the environment in the
repository settings (Settings → Environments → *environment* →
Deployment branches and tags).

Prefer an explicit set of branch name patterns, but avoid a catch-all
pattern such as `*` or `**`: those match every branch and leave the
environment effectively unrestricted even though custom branch policies are
enabled. Scope the patterns to the specific branches allowed to deploy (for
example `main` or `release/*`). The "Protected branches only" option restricts
deployments **only when the repository already has branch protection rules
(or rulesets) in place** — if no branch is protected, GitHub allows every
branch to deploy, so configure branch protection first when relying on
that option.
