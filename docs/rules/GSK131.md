# GSK131 — Branch protection can be bypassed

| | |
|---|---|
| Severity | Medium |
| Scope | Repository |
| Category | branch_protection |
| Fixable | No |
| ghqr equivalent | None |

## Why it matters

Protection that administrators or bypass actors can ignore is advisory
rather than enforced: a required review, status check, or force-push
restriction can be skipped without leaving a trace of an approval, which
is exactly the path an attacker takes after compromising an admin account.

This rule reports two ways the default branch protection can be bypassed:

- Classic branch protection with "Do not allow bypassing the above
  settings" disabled (`enforce_admins` is off).
- An active ruleset targeting the default branch that grants a bypass
  actor the `always` or `exempt` bypass mode.

The rule is skipped when:

- The default branch has no protection at all — GSK110 reports that instead.
- The repository has only one member and an approving review is required:
  the sole member cannot approve their own pull request, so a bypass is the
  only way to merge and removing it would lock the repository. This also
  covers the `gh-secure-kit/branch-protection-review` ruleset created by
  `recommended apply`, which exempts the owner for exactly this reason.

A ruleset is not trusted by its name: once the repository has another member
who can approve, an owner exemption is a real bypass and is reported.

## How to check

```sh
gh secure-kit recommended check -R OWNER/REPO --rule GSK131
```

## How to fix

For classic branch protection, enable "Do not allow bypassing the above
settings" under **Settings → Branches → Branch protection rules**.

For rulesets, remove the bypass actors, or lower their bypass mode to
"Pull requests only", under **Settings → Rules → Rulesets**.

Not auto-fixed by `recommended apply`: whether to keep an emergency bypass
for administrators or a release automation app is an operational policy
decision, and removing a bypass can block the only path to merge.
