# GSK132 — GITHUB_TOKEN default permissions are read-write

| | |
|---|---|
| Severity | High |
| Scope | Repository |
| Category | actions |
| Fixable | Yes (`recommended apply`) |
| ghqr equivalent | None |

## Why it matters

When the default `GITHUB_TOKEN` permissions are set to read-write, every
workflow run in the repository is granted write access to contents, issues,
pull requests, packages, and more unless it explicitly scopes down its own
`permissions:` block. A compromised dependency or a maliciously crafted
workflow trigger can use that ambient write access to push code, create
releases, or tamper with the repository.

## How to check

```sh
gh secure-kit recommended check -R OWNER/REPO --rule GSK132
```

## How to fix

```sh
gh secure-kit recommended apply -R OWNER/REPO --rule GSK132
```
