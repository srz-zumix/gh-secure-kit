# GSK105 — Code scanning default setup not configured

| | |
|---|---|
| Severity | High |
| Scope | Repository |
| Category | security |
| Fixable | Yes (`recommended apply`) |
| ghqr equivalent | repo-sec-008 |

## Why it matters

Code scanning analyzes source code for security vulnerabilities and coding
errors. Without it, common vulnerability classes (SQL injection, XSS, etc.)
can be merged without detection.

## How to check

```sh
gh secure-kit recommended check -R OWNER/REPO --rule GSK105
gh secure-kit code-scanning default-setup get -R OWNER/REPO
```

## How to fix

```sh
gh secure-kit recommended apply -R OWNER/REPO --rule GSK105
```

This enables CodeQL's default setup, which is what this rule checks for.
Note that GSK105 verifies the code scanning **default setup** state
specifically: if you intentionally rely on an advanced/custom CodeQL
workflow (`.github/workflows/codeql.yml`) instead of default setup, this
rule will still report it as not configured, so ignore it with
`--ignore GSK105` in that case.
