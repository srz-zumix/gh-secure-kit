# GSK135 — Environment with secrets has no required reviewers configured

| | |
|---|---|
| Severity | Medium |
| Scope | Repository |
| Category | environments |
| Fixable | No |
| ghqr equivalent | None |

## Why it matters

An environment that holds secrets but has no required reviewers lets any
workflow run that targets it proceed straight to deployment, exposing
those secrets without a human checking the change first. Environments
without any secrets are not flagged, since they have nothing sensitive for
a reviewer to gate.

## How to check

```sh
gh secure-kit recommended check -R OWNER/REPO --rule GSK135
```

## How to fix

Add one or more required reviewers to the environment's protection rules.
The safest way is the repository settings UI (Settings → Environments →
*environment* → Required reviewers), because the environment endpoint is a
full `PUT`: any protection field you omit (wait timer, deployment branch
policy, prevent self-review) is reset to its default, which would weaken the
environment's protection.

If you script it instead, first read the environment's current configuration
and send it back together with the new reviewers so existing protections are
preserved. Reviewers are an array of objects with a numeric `id`, so pass a
JSON body (`-f` fields cannot build nested objects). Replace every value below
with the environment's current settings and a real reviewer ID:

```sh
gh api --method PUT repos/OWNER/REPO/environments/ENVIRONMENT_NAME \
  --input - <<'JSON'
{
  "wait_timer": 0,
  "prevent_self_review": true,
  "reviewers": [
    { "type": "User", "id": 1234567 }
  ],
  "deployment_branch_policy": null
}
JSON
```
