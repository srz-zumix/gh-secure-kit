# GSK135 — Environment with secrets has no required reviewers configured

| | |
|---|---|
| Severity | Medium |
| Scope | Repository |
| Category | environments |
| Fixable | No |
| ghqr equivalent | None |

## Why it matters

An environment that holds secrets but has no required reviewers lets any
workflow run that targets it proceed straight to deployment, exposing
those secrets without a human checking the change first. Environments
without any secrets are not flagged, since they have nothing sensitive for
a reviewer to gate.

## How to check

```sh
gh secure-kit recommended check -R OWNER/REPO --rule GSK135
```

## How to fix

Add one or more required reviewers to the environment's protection rules
in the repository settings (Settings → Environments → *environment* →
Required reviewers), or via the API. Reviewers are an array of objects, so
pass a JSON body instead of `-f` fields (which cannot build nested objects):

```sh
gh api --method PUT repos/OWNER/REPO/environments/ENVIRONMENT_NAME \
  --input - <<'JSON'
{
  "reviewers": [
    { "type": "User", "id": USER_ID }
  ]
}
JSON
```
