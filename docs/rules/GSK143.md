# GSK143 — No push ruleset restricting pushed files

| | |
|---|---|
| Severity | Info |
| Scope | Repository |
| Category | security |
| Fixable | No |
| ghqr equivalent | None |

## Why it matters

`.gitignore` only helps on the local machine: a forgotten entry or
`git add --force` still commits files such as private keys, `.env` files,
or Terraform state. A push ruleset is enforced by GitHub on every push, so
it can reject such files, files with certain extensions, overly long paths,
or oversized files regardless of how they were committed.

The rule passes when an active push ruleset restricts file paths, file
extensions, file path length, or file size. It is evaluated only for
private and internal repositories (push rulesets apply to a repository and
its fork network).

## How to check

```sh
gh secure-kit recommended check -R OWNER/REPO --rule GSK143
```

## How to fix

Create a push ruleset in the repository (Settings → Rules → Rulesets → New
ruleset → New push ruleset), or at the organization level to cover every
repository. Typical rules:

- Restrict file extensions, for example `.pem` and `.envrc`
- Restrict file paths, for example `**/.terraform/**`
- Restrict file size, for example 10 MB

Not auto-fixed by `recommended apply` because the right file patterns
depend on the repository.
