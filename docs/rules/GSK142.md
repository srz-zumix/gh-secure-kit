# GSK142 — Forking allowed on private or internal repository

| | |
|---|---|
| Severity | Medium |
| Scope | Repository |
| Category | access_control |
| Fixable | Yes (`recommended apply`) |
| ghqr equivalent | None |

## Why it matters

Anyone with read access to a private or internal repository can fork it,
creating a copy that is outside the control of the repository's access
rules. Forks of internal repositories are readable by every member of the
enterprise, and a departing or compromised account can copy the code
without any trace in the source repository's settings. Disabling forking
keeps the code inside the repository.

Public repositories are skipped. Organization owners can also restrict
forking of all private repositories (GSK509).

## How to check

```sh
gh secure-kit recommended check -R OWNER/REPO --rule GSK142
```

## How to fix

```sh
gh secure-kit recommended apply -R OWNER/REPO --rule GSK142
```

Existing forks are not deleted; only new forks are prevented.
