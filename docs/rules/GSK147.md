# GSK147 - Secret scanning validity checks not enabled

| | |
| --- | --- |
| Severity | Medium |
| Scope | Repository |
| Category | security |
| Fixable | No |
| ghqr equivalent | None |

## Why it matters

Validity checks help prioritize exposed credentials by checking whether they
are active. GitHub sends supported detected credentials to their issuers for
verification; review this data sharing before enabling the feature.

The rule reads `secret_scanning_validity_checks` from the repository's security
settings. It skips when secret scanning is disabled or the status is unavailable.

The setting is only available for organization-owned repositories, so the rule
skips for user-owned repositories or when the owner type is unavailable.

## How to check

```sh
gh secure-kit recommended check --repo OWNER/REPO --rule GSK147
```

## How to fix

Enable validity checks under the repository's Advanced Security settings after
reviewing the prerequisites and privacy implications. This rule is read-only.
