# GSK512 — GITHUB_TOKEN default permissions are read-write

| | |
|---|---|
| Severity | High |
| Scope | Organization |
| Category | actions |
| Fixable | Yes (`recommended apply`) |
| ghqr equivalent | None |

## Why it matters

When the organization-wide default `GITHUB_TOKEN` permissions are
read-write, every workflow run in every repository that inherits this
setting is granted write access to contents, issues, pull requests,
packages, and more unless it explicitly scopes down its own
`permissions:` block. A compromised dependency or a maliciously crafted
workflow trigger in any repository can use that ambient write access to
push code, create releases, or tamper with the repository.

## How to check

```sh
gh secure-kit recommended check -o ORG --rule GSK512
```

## How to fix

```sh
gh secure-kit recommended apply -o ORG --rule GSK512
```
