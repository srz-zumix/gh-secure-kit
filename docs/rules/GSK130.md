# GSK130 — Linear history not required

| | |
|---|---|
| Severity | Info |
| Scope | Repository |
| Category | branch_protection |
| Fixable | No |
| ghqr equivalent | None |

## Why it matters

Without requiring a linear history, merge commits can obscure the exact
sequence of changes landing on the default branch, making history harder
to audit. This is mainly a readability and auditability preference rather
than a strong security control, and combining it with GSK118 (signed
commits) effectively rules out rebase merges, since GitHub does not sign
the commits it creates for a rebase merge.

## How to check

```sh
gh secure-kit recommended check -R OWNER/REPO --rule GSK130
```

## How to fix

Enable "Require linear history" under **Settings → Branches → Branch
protection rules**. Not auto-fixed by `recommended apply` since it changes
which merge methods a repository can use.
