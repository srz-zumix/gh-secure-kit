# GSK519 — Private fork pull request workflows receive write tokens or secrets

| | |
|---|---|
| Severity | High |
| Scope | Organization |
| Category | actions |
| Fixable | Yes (`recommended apply`) |
| ghqr equivalent | None |

## Why it matters

Private and internal repositories can allow workflows to run for pull
requests from forks. When those runs also receive a write-scoped
`GITHUB_TOKEN` or secrets and variables, anyone able to fork the
repository can have their code executed with those credentials. Setting
the policy at the organization level covers every repository that does not
override it.

The rule fails when fork pull request workflows are enabled and receive
write tokens, or secrets and variables.

## How to check

```sh
gh secure-kit recommended check -o ORG --rule GSK519
```

## How to fix

```sh
gh secure-kit recommended apply -o ORG --rule GSK519
```

The fix stops sending write tokens and secrets to fork pull request
workflows and leaves the other settings unchanged.
