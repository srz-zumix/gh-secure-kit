# GSK518 — Immutable releases not enforced for all repositories

| | |
|---|---|
| Severity | Medium |
| Scope | Organization |
| Category | security |
| Fixable | No |
| ghqr equivalent | None |

## Why it matters

Immutable releases freeze the assets and the tag of a published release so
that an attacker cannot swap a binary after the fact. Enforcing the
setting at the organization level protects every repository without
relying on each repository owner to enable it (see GSK139).

The rule passes only when immutable releases are enforced for all
repositories; both "selected repositories" and "none" fail.

## How to check

```sh
gh secure-kit recommended check -o ORG --rule GSK518
```

## How to fix

Enable the enforcement in **Organization settings → Repository → Releases
→ Immutable releases**. Not auto-fixed by `recommended apply` because the
setting affects every repository: workflows that upload assets after
publishing a release will fail, and must first be changed to create a
draft release, upload all assets, and then publish the draft.
