# GSK517 — Actions SHA pinning not required

| | |
|---|---|
| Severity | High |
| Scope | Organization |
| Category | actions |
| Fixable | Yes (`recommended apply`) |
| ghqr equivalent | None |

## Why it matters

A workflow that references an action by tag or branch (for example
`actions/checkout@v4`) runs whatever that tag points to when the job
starts. Tags can be moved, so a compromised action repository can ship
malicious code to every consumer without any change to your workflow.
Requiring actions to be pinned to a full-length commit SHA across the
organization makes GitHub reject any workflow that uses a mutable
reference, in every repository.

## How to check

```sh
gh secure-kit recommended check -o ORG --rule GSK517
```

## How to fix

```sh
gh secure-kit recommended apply -o ORG --rule GSK517
```

Enabling the policy makes existing workflows that use tag references fail
in every repository of the organization, so pin the actions first and then
apply the fix.
