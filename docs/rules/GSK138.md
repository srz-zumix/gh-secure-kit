# GSK138 — Actions SHA pinning not required

| | |
|---|---|
| Severity | High |
| Scope | Repository |
| Category | actions |
| Fixable | Yes (`recommended apply`) |
| ghqr equivalent | None |

## Why it matters

A workflow that references an action by tag or branch (for example
`actions/checkout@v4`) runs whatever that tag points to when the job
starts. Tags can be moved, so a compromised action repository can ship
malicious code to every consumer without any change to your workflow. This
is how the `tj-actions/changed-files` incident spread. Requiring actions to
be pinned to a full-length commit SHA makes GitHub reject any workflow that
uses a mutable reference.

## How to check

```sh
gh secure-kit recommended check -R OWNER/REPO --rule GSK138
```

## How to fix

```sh
gh secure-kit recommended apply -R OWNER/REPO --rule GSK138
```

Enabling the policy makes existing workflows that use tag references fail,
so pin the actions to commit SHAs first and then apply the fix.
