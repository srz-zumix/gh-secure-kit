# GSK141 — Private fork pull request workflows receive write tokens or secrets

| | |
|---|---|
| Severity | High |
| Scope | Repository |
| Category | actions |
| Fixable | Yes (`recommended apply`) |
| ghqr equivalent | None |

## Why it matters

Private and internal repositories can allow workflows to run for pull
requests from forks. When those runs also receive a write-scoped
`GITHUB_TOKEN` or the repository's secrets and variables, anyone able to
fork the repository can have their code executed with those credentials. A
fork owner who is not fully trusted, or a compromised account, can
exfiltrate secrets or push malicious changes.

The rule fails when fork pull request workflows are enabled and receive
write tokens, or secrets and variables. Public repositories are skipped.

## How to check

```sh
gh secure-kit recommended check -R OWNER/REPO --rule GSK141
```

## How to fix

```sh
gh secure-kit recommended apply -R OWNER/REPO --rule GSK141
```

The fix stops sending write tokens and secrets to fork pull request
workflows and leaves the other settings unchanged. Consider also disabling
forking entirely (GSK142).
