# GSK538 - Default configurations do not enable secret scanning validity checks

| | |
| --- | --- |
| Severity | Medium |
| Scope | Organization |
| Category | security |
| Fixable | No |
| ghqr equivalent | None |

## Why it matters

Validity checks can prioritize active exposed credentials. This rule reads
`secret_scanning_validity_checks` in
[default security configurations](README.md#organization-security-configuration-checks)
and skips a configuration when secret scanning is disabled.

## How to check

```sh
gh secure-kit recommended check --owner ORG --rule GSK538
```

## How to fix

Review the privacy implications before enabling validity checks in applicable
default configurations: GitHub sends supported detected credentials to their
issuers for verification. This rule is read-only.
