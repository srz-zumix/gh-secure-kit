# GSK523 - Self-hosted runner group allows public repositories

| | |
|---|---|
| Severity | High |
| Scope | Organization |
| Category | actions |
| Fixable | Yes |
| ghqr equivalent | None |

## Why it matters

Untrusted workflow code from a public repository can compromise a self-hosted
runner, steal credentials, reach internal services, or persist into later jobs.
Fork workflow approval reduces exposure but does not provide runner isolation.

This rule flags runner groups with `allows_public_repositories=true`, even if
the organization currently has no public repositories or the group is empty.
It checks permission configuration, not whether untrusted code has executed.
Repository visibility and workflow restrictions may reduce actual exposure.
Groups used only for isolated GitHub-hosted larger runners have a different
risk profile and require manual assessment.

## How to check

```sh
gh secure-kit recommended check --owner my-org --rule GSK523
```

## How to fix

```sh
gh secure-kit recommended apply --owner my-org --rule GSK523
```

This sets `allows_public_repositories=false` only on groups permitting public
repositories and preserves other settings. It can prevent public workflows
from scheduling jobs. Inherited groups must be changed at the enterprise level;
apply reports an error before changing any groups when one is inherited.
