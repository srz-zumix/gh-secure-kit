# GSK526 - Actions lockfile not required for all repositories and workflows

| | |
|---|---|
| Severity | High |
| Scope | Organization |
| Category | actions |
| Fixable | No |
| ghqr equivalent | None |

## Why it matters

A workflow dependency lockfile records the commit resolved for each action
dependency, including transitive dependencies. The **Require lockfile** policy
blocks targeted workflows that have not been onboarded to a lockfile.

This rule checks the policy setting, not the contents or validity of individual
lockfiles. It passes only if one active organization or inherited enterprise
policy requires a lockfile for every repository and every workflow in the
organization. Multiple partial policies are not combined. When Actions is
disabled for all repositories, or policy availability or coverage cannot be
determined, the rule is skipped. Authentication and permission errors are
reported instead of being treated as skipped checks.

## How to check

```sh
gh secure-kit recommended check --owner ORG --rule GSK526
```

## How to fix

Onboard and verify workflows in the organization's repositories, then configure
an active **Require lockfile** policy targeting all repositories and workflows,
either on the organization or at the enterprise level. Enabling the policy
before onboarding blocks targeted workflows that are not covered. This rule
does not automatically change the policy or create lockfiles.
